# 登录功能 — 需求分析（PRD）

> **需求来源：** 一段话「做一个登录功能」+ 澄清「需要做登录和注册页面」+ 澄清「增加管理员和用户区分：管理员登录进观测界面，用户进面试界面」  
> **功能短名：** `login`  
> **产出路径：** `docs/login/需求分析.md`  
> **状态：** DRAFT — 待确认项已全部拍板并写入正文  
> **边界：** 本文只写 *what / why*，不写具体接口字段、库表 DDL、技术选型或任务拆分

---

## 1. 问题（Problem）

InterviewAgent 同时服务两类人：

1. **普通用户（求职者）** 需要登录后做模拟面试，并让记忆/薄弱点/面试历史归属本人；  
2. **管理员（研发/运维）** 需要进入全链路观测界面做排查与统计。

当前问题：

- 求职者侧缺少登录/注册页与强制身份闭环；  
- 观测侧靠共享 Admin Token，**不是账号登录**，与「管理员登录进观测」的产品预期不一致；  
- 没有角色区分时，无法保证「管理员进观测、用户进面试」的分流与互斥访问。

---

## 2. 证据（Evidence）

- 产品内观察：存在可选 JWT 注册/登录；观测页曾依赖 `X-Obs-Admin-Token`；主流程无登录页。  
- 需求澄清（已确认）：独立登录/注册页；强制登录；用户绑定个人数据；**ADMIN→观测、USER→面试**；观测改为管理员 JWT（去除 Admin Token）；管理员无面试能力等（见 §8）。

---

## 3. 用户（Users）

- **Primary — 普通用户（USER）：** 校招/初级 Java 求职者；注册/登录后进入**面试界面**。  
- **Primary — 管理员（ADMIN）：** 研发/运维；登录后进入**观测界面**，**无面试能力**。  
- **Not for：** 企业 SSO、OAuth、多于两角色的 RBAC、同机一键切换账号。

---

## 4. 假设（Hypothesis）

我们认为：**用账号角色区分管理员与普通用户，登录后分别进入观测界面与面试界面，并强制身份闭环**，将同时满足求职者数据归属与研发观测入口统一到「登录」体验。  

验证标准：USER 进面试且不可观测；ADMIN 进观测且不可面试；未登录不可用两端；误入自动回到本角色落地页；用户数据按人隔离。

---

## 5. 成功指标（Success Metrics）

| 指标 | 目标 | 度量方式 |
|------|------|----------|
| 登录分流 | USER→面试；ADMIN→观测 | 双角色验收 |
| 互斥访问 | USER 不可观测；ADMIN 不可面试；误入**自动跳转**本角色落地页 | 交叉验收 |
| 注册页可用 | 仅 USER；成功进面试界面 | 手工验收 |
| 强制登录 | 未登录不可用面试/观测 | 手工验收 |
| 会话保持 | 关浏览器仍登录直至登出/过期 | 重开页 |
| 身份归属 | 记忆/薄弱点/历史按 USER 隔离 | 双账号 |
| 错误可理解 | 区分用户不存在/密码错；登录加限流 | 用例 |
| 密码能力 | 邮箱找回（邮箱不存在则报错）；改密后**强制重新登录** | 用例 |

---

## 6. 范围（Scope）

### 6.1 MVP — 必须交付

1. **角色 USER / ADMIN**  
   - USER→面试界面；ADMIN→观测界面。  
   - 自助注册仅 USER。  
   - 管理员来源：**环境预置（启动种子）** + **已有管理员可创建另一个管理员**。  
   - ADMIN **没有**面试能力（不可用聊天/开面试/WS）。

2. **独立登录/注册页**；登录失败区分用户不存在与密码错误；登录接口加限流。

3. **强制登录**；WS 仅 USER 且必须带身份，否则「用户未登录」。

4. **页面误入：** 自动跳转到自己的落地页（非冷 403 页）。

5. **会话：** 关浏览器保持登录；无 refresh；登出回登录页。

6. **数据归属：** 记忆/薄弱点/面试历史；观测可按 `userId` 区分。

7. **找回/改密：** 邮箱验证码找回（**邮箱不存在则明确报错，不隐藏**）；改密独立页；USER/ADMIN 共用；改密成功后**强制重新登录**。

8. **观测鉴权：** **完全改为 ADMIN JWT**；**去除** `OBS_ADMIN_TOKEN` / `X-Obs-Admin-Token` 主路径与过渡双支持。

### 6.2 不做范围

- OAuth / SSO / 复杂 RBAC / 设备风控 / 一键切换账号  
- 共享 Admin Token 作为观测入口  
- 管理员使用面试主流程

## 8. 已拍板结论（原待确认）

| 议题 | 结论 |
|------|------|
| 管理员如何创建 | **环境预置** + **已有管理员创建另一个管理员** |
| 误入页面 | **自动跳转**到本角色落地页 |
| 观测 API 鉴权 | **完全改为 ADMIN JWT**；**去除** OBS_ADMIN_TOKEN |
| 管理员面试能力 | **没有** |
| 登录限流 / 找回隐藏邮箱 | **加限流**；找回**不隐藏**（邮箱不存在则报错） |
| 改密成功后 | **强制重新登录** |

此前已拍板项（登录页、注册、强制登录、密码规则、无 refresh、角色分流等）仍然有效。

## 9. 风险

| 风险 | 缓解 |
|------|------|
| 自助注册抬权 | 注册固定 USER；ADMIN 仅预置或 ADMIN 创建 |

| 去除 Admin Token 后旧习惯断裂 | 文档与观测页改为管理员登录 |
| 找回暴露邮箱是否存在 | 产品已接受；配合发送/登录限流 |
